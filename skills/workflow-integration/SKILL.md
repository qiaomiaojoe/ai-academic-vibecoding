# 工作流整合 · 把管线接起来

**这个 skill 处理的是卡与卡之间那条缝。**

学员的工作台跑不通，十次有八次不是哪张卡写坏了，是**卡与卡之间没有合约**：
第二张卡不知道第一张卡把东西写到哪了，于是它问学员要路径；学员手打一个，打错一个字就读不到；
AI 读不到又不肯认，照着文件名脑补出一份像模像样的内容——**整条流水线从这里开始骗人。**

## 为什么是现在做，不是一开始做

建项目的时候工作流还没定，那时候只能给一套万能文件夹——**对谁都成立，也就对谁都不精确。**
卡片拿不到精确的位置，只好回头问人，于是每张卡都多出几个必填项。

**工作流一旦定下来，文件夹体系就不再是猜的了**：一道工序一个文件夹，上游产出在哪用肉眼就能看出来。
所以这一步必须等工作流确定之后做，而且**做完要往回改**——改 AGENTS.md，也改每一张已经搭好的任务卡。

## 这个 skill 不做什么

- **不设计工作流**，那是 `workbench-builder`。工作流是它的产出，是本 skill 的输入。
- **不设计方法**，那是 `skill-forge`。工序里"干什么"只写一行，不展开成方法。
- **不改长相**，那是 `workbench-design`。本 skill 碰 HTML 只碰 prompt 模板和输入框，不碰样式。

---

## 硬约束（违反任何一条都算没做对）

1. **两遍法。** 第一遍只出合约（工序链 + 交接表 + 改动清单），**停下来等确认**；第二遍才动文件。
2. **动手前先备份。** 工作台 HTML 和 AGENTS.md 各拷一份带时间戳的副本，告诉学员备份在哪。
   **这一步会改动能跑的东西，没有备份不许开工。**
3. **不替学员发明工序。** 工序链从现有的卡和工作流设计里**读出来**，不是问出来、更不是编出来。
   读不出来的标 `【待补：…】`，不许用通用学术流程填上。
4. **"读什么"那一列不许写"相关材料"。** 必须写**具体的文件名模式**（`文献清单.md`、`M*.md`）。
   写不出文件名模式，说明上游那道工序的产出形态还没定——回去定，别往下走。
5. **每份产出必须有下家，每个输入必须有上家。** 两个方向都要闭合，见第 3 步。
6. **上游没跑过，下游必须明说读不到。** 每道工序都要写明这一条的行为，**不许脑补上游的内容**。
   这是整张合约里最要紧的一格。
7. **改任务卡一次只改一张。** 改完让学员在浏览器里点一遍那张卡、看生成的 prompt 变了、控制台没报错，再改下一张。
8. **砍输入框要先出清单等确认，不许顺手砍。** 砍掉一个框就是改功能——列出"哪个框、为什么能砍、砍了从哪读"，学员点头才动。
9. **磁盘上已有的产出默认不动。** 要按新结构搬，先备份、先出对照表、学员确认，一份都不许静悄悄移走或改名。
10. **合约落成单独文件，不塞进 AGENTS.md。** AGENTS.md 里只留一行链接指过去——
    文件名和路径会变，写进 AGENTS.md 就成了每次请求都加载的过期信息。

## 第 1 步 · 把现在的工作流读出来

**从项目里读，不要问学员"你的工作流是什么"**——他要是答得上来，就不需要这一步了。

按顺序读这几样：工作台 HTML 里的每一张任务卡（它的输入框、它调哪个 skill、它的落盘段怎么写的）、
工作流设计文件、`AGENTS.md`。读完排成一张工序链：

| # | 这道工序干什么 | 做完手里有什么（产出形态） | 现在是哪张卡 |
|---|---|---|---|
| 01 | 收集要读的文献 | 一份带题录（作者/年份/DOI）的清单 | 卡「文献检索」 |
| 02 | 逐篇读成结构化批注 | 每篇一份批注 | 卡「精读」 |
| 03 | 把批注汇总成综述素材 | 一份按主题归并的素材 | 卡「汇总」 |

**产出形态要写得能验收**："一份清单"不行，"一份带题录的清单"才行。
形态说不清的那道工序，就是学员自己也还没想清楚的那道——**标出来，别替他想清楚。**

贴给学员确认一次：**"你现在的活儿是这三道，对吗？"** 这是第一个停点。

## 第 2 步 · 由工序链反推文件夹

**一道工序一个文件夹，编号就是工序号。** 这样"上游的东西在哪"用肉眼就能看出来，不用记。

```
<项目名>/
  AGENTS.md  CLAUDE.md
  工序与交接.md                   ← 本 skill 写
  工作台/  skills/  skill源材料/  日志/
  产出/
    <任务标识>/                   ← 每跑一个具体任务（一篇论文、一个课题）建一个
      01_文献清单/
      02_批注/
      03_综述素材/
```

**`产出/` 下面先分任务、再分工序，这一层不许省。**
省掉它，第二篇论文跑起来就会覆盖第一篇——而且是静悄悄地覆盖。

已经有产出的项目，按硬约束 9 办：**先只把结构建出来，旧文件原地不动**，
学员要搬再单出一张「旧文件 → 新位置」对照表给他确认。

## 第 3 步 · 填交接表（这一步是整个 skill 的正题）

每道工序一行，**六列一个都不能空**：

| # | 读什么（上游文件名模式） | 干什么 | 写到哪 | 文件怎么命名 | 上游没跑怎么办 |
|---|---|---|---|---|---|
| 01 | 无（起点，读用户当场给的检索词） | 检索并整理 | `产出/<任务>/01_文献清单/` | `文献清单.md`，重跑加 `-R2` | — |
| 02 | `01_文献清单/文献清单.md` | 逐篇读成批注 | `产出/<任务>/02_批注/` | `<引用键>.md`，一篇一份 | 明说「没读到 01 的文献清单」，停下问我，**不许自己编一份清单** |
| 03 | `02_批注/*.md` | 归并成素材 | `产出/<任务>/03_综述素材/` | `综述素材.md` | 明说读到几份、少了哪些，不足三份先问我要不要继续 |

填表纪律：

- **命名规则里必须带重跑策略。** 同一道工序跑第二轮另存 `-R2`，不许覆盖——这和 AGENTS.md 的通用底线是同一条，这里是它的具体形态。
- **"读什么"写模式不写绝对路径。** `02_批注/*.md` 可以，`/Users/xxx/…` 不行，换台电脑就废了。
- **"上游没跑怎么办"不许写"报错"。** 要写清**说什么话**——"明说没读到 01 的文献清单"。
  这一列的存在意义就是把硬约束 6 落到每一道工序上。

### 接不上检查（贴给学员之前自己先跑一遍）

发现断点就地修，**不要交一张漏的表**：

1. **每份产出有没有下家？** 没人读的产出只有两种解释：它是终点产物，或者**这道工序是多余的**。是哪种，问学员。
2. **每个输入有没有上家？** 没有任何工序产出它，说明**中间缺了一道工序**，或者它该由用户当场填。是哪种，问学员。
3. **还有没有哪张卡要用户手打路径？** 有就是合约没定到位——路径该由合约推出来，不该由人记。
4. **有没有哪个输入，上游已经产出过了还让用户再填一次？** 有就该砍，按硬约束 8 先出清单。

> **表单每多一个必填项，就是把一次判断甩回给用户。**
> 工作台是替人做判断的，不是替人填表的。而这里绝大多数必填项的成因只有一个：**上下游没有合约。**

合约和改动清单一起贴给学员。**这是第二个停点，也是最后一个**——他点头之后才动文件。

---

## 第 4 步 · 把合约推下去（确认后，一件一件来）

### ① 落 `工序与交接.md`

工序链表 + 六列交接表 + 一句「工作流改了就回来改这张表」。这是唯一的权威副本。

### ② 改 AGENTS.md

只动「命名与落盘」这一节，**其余一个字不碰**。替换成两行：

```markdown
## 命名与落盘
业务产出一律落在 `产出/<任务标识>/<工序号>_<工序名>/`，Markdown 格式，开头注明日期和本次输入摘要。
每道工序读什么、写到哪、上游缺了怎么办，见 `工序与交接.md`——动手前先读它，不要凭印象猜路径。
```

**不要把整张交接表抄进 AGENTS.md。** 改完把这一节的前后对照给学员看。

### ③ 逐张改任务卡的 prompt

**一次一张**（硬约束 7）。每张卡按同一套规格改，只改这三处：

| 改哪儿 | 改成什么 |
|---|---|
| **context 里的"读什么"** | 写死成交接表里那一行的文件名模式，**并写明读不到时说什么话**——不许脑补上游内容 |
| **落盘段的"写到哪"** | 写死成交接表里的目录和命名规则，**含重跑另存 `-R2`** |
| **上游已产出的输入框** | 按第 4 问的清单砍掉，改成从上游文件读；`buildContext()` 里对应那段一并删干净 |

**不要顺手改这张卡的方法、字段语义、布局和样式。** 那是别的 skill 的活儿。

每改完一张：让学员在浏览器里打开工作台、点一遍那张卡、看生成的 prompt 里路径确实变了、控制台没报错。
**这一张验过了，再动下一张。**

改完全部之后，工作台要按项目约定升 `WB_VERSION`、在 CHANGELOG 记一条、跑一次快照。

---

## 产出与完成标准

交付时给三样：**工序链表**（学员认过的）、**六列交接表**（填满、两个方向闭合）、**改动清单**（AGENTS.md 改了哪一节、每张卡改了哪三处、砍了哪几个框）。

**完成标准：随便指着工作台上的任何一张卡，都能当场回答这三句话——**

- 它读的东西是谁写的、写在哪；
- 它写的东西谁会来读；
- 上游没跑的时候它会说什么（**必须是"我没读到 xx"，不是一份看起来很像的东西**）。

三句里有一句答不上来，这张合约就还没做完。

**外加一条底线：改完之后整条流水线要能从头跑一遍。** 跑不通就先退回备份，别在坏的基础上接着改。
