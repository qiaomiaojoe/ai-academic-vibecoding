# 工作台试跑与修复

作为 workbench-builder 搭建后的内部工具自动执行，不在开发工作台增加独立任务卡或验收配置模块。收到搭建工具交接时，沿用本产品内技术修复授权，试跑、修复、复测连续完成；不要求用户另发指令。

独立调用时仍按用户范围区分只检查和修复。明确只检查时不修改代码；搭建后的自动调用使用修复模式。学术/业务决定不由技术修复代替。

## 定位与依据

读取项目根目录、项目指令、设计（默认 `工作台设计.md`）、工作源 HTML、关联 skills 和测试材料。根目录未给时按项目名在当前目录及直接子目录定位；缺失、多匹配、工作源不明确时问清。

读功能清单、确认范围、输入输出、停点及绑定版本。没设计时可检查现有行为并草拟验收范围，但要指出未确认要求，不能按猜测宣布完成。部分场景检查只能给部分结论。

用材料副本，在 `产出/验收/<本次运行标识>/` 隔离结果，核对每个生成指令的实际输出路径。不破坏原稿、业务结果或历史记录。没有真实材料就说明缺什么；可用标为模拟的材料测机制，不称为真实业务验收。

## 试跑

1. **静态与页面**：能否打开、导航/按钮是否有效、输入是否进入 prompt、共享信息是否传递、方法路径是否存在、输出是否按任务/轮次隔离。能控制浏览器就实际操作；只能读源码则注明静态检查，不声称按钮已验证。
2. **正常路径**：从工作台生成真实指令并执行，记录材料、方法版本、产物和结果，核对实际读取指定上游。缺工具/权限/额度则记受阻，不用模拟补成通过。
3. **分支与异常**：按职责选关键边界，不凑数量。检查缺上游、未确认上游、多轮版本、不同任务串档、方法资料不足。作者决定点必须保留；测试可以提供标明的测试决定，不能替作者作真实决定。
4. **业务对应**：逐功能核对证据。审稿看意见原文编号、作者决定、实际修改差异与位置、回复所述动作；没补分析不能声称已做。投稿包按提供的期刊要求检查，不伪称正式提交。

正式发送、投稿、发布、账号修改不属于默认试跑；有明确授权按授权处理，其余以本地产物验收。

## workflow / subagent 的运行检查

项目包含 `工作台配置.json` 或运行组件时，核对 schema、运行组件版本、manifest 文件清单与实际校验值。确认产品自己的运行机制支持下列行为，而非仅在开发对话里描述过：

- workflow：正常通过、失败退回、返工结果失效、已验收上游交接、次数上限、不同任务隔离、重启恢复。
- subagent：同组角色独立并行；汇总在下游且实际拿到上游；任一角色错误/超时/格式不符不能宣告成功，分歧进入人工判断。
- 内部质量检查：形式检查与业务判断分开，人工判断记录依据，程序检查失败不能用“人工通过”绕开，重复点击及旧状态提交不重复执行。

运行记录中的 demo / codex 模式和配置快照需核实；模拟只证明机制。角色 instructions 是否包含确认的方法正文、提供的材料是否真实读取必须另外检查。CLI 不可用记受阻，不降级为模拟通过。缺少业务材料不妨碍机制检查，但不能给业务总体通过。

## 定位、修复、复测

分类为设计、skill 方法、界面/指令生成、文件/版本交接、环境依赖。每项记稳定 ID、复现输入、预期、实际、证据、影响场景、建议修复。

只验收仅写报告，不改代码、方法或标准。修复模式按根因改最小范围：设计决定改变需用户决定，技术修复沿用授权，不降低验收标准抹去失败。修改前唯一备份，更新受影响方法、绑定、HTML 版本和日志。

重跑原失败用例及受共享逻辑影响场景。同一原因连续两次修复无改善且没有新证据时，停下记录未解决问题，不无限重写。环境阻塞说明恢复条件，继续其他检查。

## 报告与反馈

简要报告写 `日志/试跑-<运行标识>.md`，原始测试数据和文件校验值放 `日志/开发验证/<版本>/`；`工作台版本/` 只存快照与 CHANGELOG。报告包括：范围、设计/产品/方法版本、材料是否模拟、逐功能通过/失败/受阻/未测试、证据、已修与未解决问题、复测结果。通过要有实际证据；范围内全部必须功能及关键分支达标才给总体通过。

更新设计状态并链接报告，不改功能要求。区分页面可用、方法可调用、业务完成；能生成 prompt 只支持第一层。

确有通用工具缺陷时写 `日志/开发工具改进建议-<运行标识>.md`：复现事实、对应开发工具、最小修订、适用范围、回归用例。没有就不造空文件，不把单个期刊要求升级成通则。

用户明确授权回写开发工具时，定位开发工具仓库源文件后修改复测，不把业务目录或全局副本当源。未授权只给建议，不自动修改全局 skills 或发布仓库。
