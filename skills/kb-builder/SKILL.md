# kb-builder · 一键建库

**核心设计只有一条：不在提问时临时翻材料，而是在录入时就编译成持久、互链的概念页。** 下面每一步都在执行它。

## 输入

| 字段 | 必填 | 默认 |
|---|---|---|
| `工作文件夹` | 是 | —— 放着原材料的文件夹，建成后它就是知识库根目录（也是 Obsidian 仓库） |
| `库名` | 否 | 文件夹名 |
| `这个库装什么` | 否 | 从材料推断，一句话 |
| `规则停点` | 否 | **关**。开 = 写规则层之前停下给用户审分类和规则草案 |
| `规则文件` | 否 | 本 skill 的 `assets/KB-SKILL-模板.md` |

路径不存在、或指向的不是文件夹 → 报出准确路径，停止，不猜其他位置。

## 第 1 步 · 判定文件夹状态（决定走哪条路）

| 状态 | 判定依据 | 默认动作 |
|---|---|---|
| **新库** | 没有 `KB-SKILL.md`，也没有 `wiki/` | 走完第 2–7 步 |
| **已有库** | 有 `KB-SKILL.md` 且有 `wiki/index.md` | **增量模式**：跳过第 3 步，不动规则层；第 4 步只处理 `wiki/log.md` 里没登记过的材料 |
| **有规则无库** | 有 `KB-SKILL.md`，没有 `wiki/` | 原样使用这份 `KB-SKILL.md`（不改一个字），从第 2 步做起，跳过第 3 步 |
| **有库无规则** | 有 `wiki/`，没有 `KB-SKILL.md` | **停下**：列出现有 wiki 结构，问用户是「按现有结构反推规则层」还是「换个文件夹另建」。不覆盖、不重排已有页 |

把判定结果写进最终报告的「模式」一栏。

## 第 2 步 · 建骨架、归置材料

```
<工作文件夹>/
├── raw/            原材料，只读
├── wiki/
│   ├── index.md    总目录
│   ├── log.md      操作日志（只追加）
│   └── <分类>/     第 3 步定
├── .kb-cache/      抽取出来的纯文本（PDF/Word 转出来的放这里，不放 raw/）
└── KB-SKILL.md     第 3 步写
```

**材料归置：**

| 情况 | 动作 |
|---|---|
| 已有 `raw/` | 只把 `raw/` 里的当材料。顶层散放的文件**不动**，列进报告「未纳入」 |
| 没有 `raw/` | 建 `raw/`，把顶层所有文件和子文件夹**移动**进去（保持子目录结构）。**跳过**：隐藏文件、`.obsidian/`、`KB-SKILL.md`、`wiki/`、`.kb-cache/`。**只移动，不删除、不改名**；逐项写进 `log.md` 的「迁移清单」，以便还原 |

**读取材料**按 [references/材料读取.md](references/材料读取.md) 逐份分类，得到一张材料清单：

`材料路径 | 类型 | 可读性（可读/跳过） | 文本来源（原文件/.kb-cache 路径） | 跳过原因`

可读材料为 0 → 建完骨架和规则层就停，不写任何概念页，报告里说明原因。

## 第 3 步 · 写规则层 KB-SKILL.md

**规则来源优先级：** 文件夹里已有的 `KB-SKILL.md`（原样用，不改）> 用户给的 `规则文件` > `assets/KB-SKILL-模板.md`。

套模板时只填四个占位：`{{库名}}` `{{这个库装什么}}` `{{用途}}` `{{分类表}}`。模板里的三层架构、页面格式、录入流程、体检、硬约束**一个字不改**——那是这套方法本身，不是可以按材料"优化"的草稿。

**定分类：** 每份可读材料读标题 + 前约 2000 字（材料超过 30 份时每类抽样读），归纳 **4–8 个分类**。产出分类表：

`分类名 | 装什么（一句话） | 依据的材料（举 1–3 份）`

- 分类按**概念领域**分（如"成本分析 / 预算编制 / 案例"），**不按材料类型分**（不许出现"讲义 / PPT / 论文"这种分类）
- 材料是连续课次或章节 → 可以加一个「来源概览」类，每份材料一页轻量概览
- 材料里有真实问答 → 加「答疑」类

**规则停点：**

| 设置 | 动作 |
|---|---|
| 关（默认） | 直接写入 `KB-SKILL.md`，建分类子文件夹，继续第 4 步。分类表放进最终报告，用户事后可改 |
| 开 | 展示「库名 / 这个库装什么 / 用途 / 分类表」和规则层全文，**等用户确认或修改后**再写入、再继续。这是本 skill 唯一的停点 |

## 第 4 步 · 逐份编译成概念页

**一份材料处理完、落盘、记账，再读下一份。** 不要先把所有材料读进来再统一写。

每份材料：

1. 读 `wiki/index.md`，知道现在库里有哪些页。
2. 读这份材料（长材料按章节或约 15000 字分段，逐段处理）。
3. 抽出材料里的**概念**，逐个判定：

   | 判定 | 依据 | 动作 |
   |---|---|---|
   | 已有页 | index 里有同一概念（同义不同名也算） | **就地更新那一页**：补新内容、`sources` 追加、`updated` 改今天 |
   | 新概念 | index 里没有 | 在对应分类下新建一页 |
   | 材料只提了名字、没讲内容 | 原文不足以写出结论 | **不建页**，在相关页里写成 `[[概念名]]` 链接，留作断链 |
   | 归不进任何分类 | —— | 放进最接近的分类，页内 `status: 存疑` 并写明"分类待定" |

4. 页面格式严格按 `KB-SKILL.md` §2：frontmatter 必填（`title / category / sources / raw / updated / status / see_also`），`see_also` 写成 `["[[概念A]]", "[[概念B]]"]`（带引号的列表，Obsidian 才认得出是链接），正文先给两三句结论再展开，引原话标出处，提到别的概念就加 `[[链接]]`。
5. `status` 判定：原文明确讲清 → `已验`；需要推断或材料间矛盾 → `存疑`（正文写明疑在哪）；来自非原材料的补充 → 不许写。
6. 更新 `index.md`（新页加一行：`- [标题](路径) — 一句话摘要 · 日期`；改过的页改日期）。
7. 在 `log.md` 里追加一条，**位置是 `# 操作日志` 标题的正下方**（最新的在最上面，标题永远是第一行）：

   `## [日期] ingest | <材料路径>` + `- 新建：… / 更新：… / 留作断链：…`

   **这条记录就是增量模式判断"录过没有"的依据**，漏记会导致下次重复录入。

## 第 5 步 · 体检

把 `assets/lint.py` 复制到库根目录并运行（`python3 lint.py`）。按结果：

| 问题 | 动作 |
|---|---|
| 重复 title（同概念两页） | **合并**：保留先建的那页，把后一页内容并入，全库改指向，删掉后一页；在 log 记一条 |
| 没被 index 收录的页 | 补进 index |
| frontmatter 缺字段 | 能从正文确定就补；确定不了的 `status` 填 `存疑` |
| 断链 | **只列出，不建页**——它们是待写清单 |

修完再跑一次 lint，把第二次的结果放进报告。没有 python3 → 按同样五项人工检查，报告里注明"lint.py 未运行"。

## 第 6 步 · 看板视图

把 `assets/知识库看板.base` 复制到 `wiki/`（已存在则不覆盖）。它按 frontmatter 生成三个视图：按状态看板 / 按分类总表 / 待补的。

**不要**替用户注册 Obsidian 仓库、不改 Obsidian 的任何配置文件。

## 第 7 步 · 报告

按这个结构输出，**每一栏都要有**。同一份内容存到库根目录的 `建库报告.md`（每次覆盖成最近一次；历史靠 `wiki/log.md`）：

```
## 建库报告 · <库名>
- 库路径：
- 模式：新库 / 已有库（增量）/ 有规则无库
- 规则来源：已有 KB-SKILL.md / 用户规则文件 / 课程模板
- 规则停点：开 / 关

### 分类表
| 分类 | 装什么 | 页数 |

### 材料处理
| 材料 | 类型 | 结果（已录入 / 跳过 / 此前已录入） | 新建页 | 更新页 | 跳过原因 |

### 库的现状（第二次体检结果）
| 概念页 | 已验 | 待验 | 存疑 | 断链 | 合并掉的重复页 |

### 迁移清单（本次移动进 raw/ 的项目；没有写"无"）

### 下一步
1. 用 Obsidian 打开：左下角库名 → 打开本地文件夹作为仓库 → 选 <库路径>。
   第一次必须在界面里打开，obsidian://open 链接只对登记过的库有效。
2. 打开 wiki/知识库看板.base 看三个视图。
3. 以后加材料：放进 raw/，再说一次"一键建库 <库路径>"，只会录入新的。
```

## 硬约束

- **原材料里没有的，不许写进 wiki。**
- **`raw/` 只读。** 除第 2 步首次归置时的移动外，不改名、不修改、不删除、不往里写任何文件。
- **不删除用户的任何文件。** 唯一允许删除的是第 5 步合并掉的重复概念页。
- **已有的 `KB-SKILL.md` 不覆盖、不"优化"。**
- **不注册 Obsidian 仓库，不改应用配置。**

## 典型失败模式

1. **你会想先把所有材料读完再统一写页**，因为感觉这样更有全局观。结果上下文被撑爆，后读的材料只剩模糊印象，页里开始出现原文没有的话。→ 一份一份处理，每份结束就落盘 + 记 log。
2. **你会想一份材料建一页**（"《第三章讲义》.md"），因为这样最省事、看起来也整齐。那是文件摘要，不是概念库，下一份材料进来无处可并，复利直接失效。→ 页按概念建；一份材料通常会更新好几个已有页。
3. **你会想给读不出来的扫描件按文件名写一页**，因为不想在报告里交一堆"跳过"。这就是编造。→ 跳过，写进材料处理表，原因写清楚。
4. **你会想把断链当场补写成页**，因为看起来不完整。原材料没讲清的概念，写出来的只能是你自己的知识。→ 断链就是待写清单，留着。
5. **增量模式下你会想顺手调整分类、改进 KB-SKILL.md**，因为看到了"更好的组织方式"。规则层一动，已有页的归类全部失效。→ 增量模式只录入，不碰规则层；有建议写进报告末尾，让用户决定。
6. **你会想把 PDF 抽出的文本存进 `raw/`**，因为放在原文件旁边方便对照。那就改了只读层，下次还会被当成新材料重复录入。→ 抽取文本一律放 `.kb-cache/`。
