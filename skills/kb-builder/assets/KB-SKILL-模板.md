## 2. 概念页格式

**一页 = 一个概念。** 同一个概念在新材料里再出现，**就地更新这一页，不另起新页**——这是"知识复利"的全部机制。

**页按概念建，不按材料建。** 不许出现"《某某讲义》.md"这种一份材料一页的页面。

frontmatter（**必填**，它就是 Obsidian Bases 视图的数据库字段，字段名不许改）：

```yaml
---
title: 概念名
category: 所属分类
sources: 来自哪些材料（多份用分号隔开）
raw: ../../raw/<原文件路径>
updated: YYYY-MM-DD
status: 已验      # 已验 = 原文明确讲清；存疑 = 需要推断或材料矛盾（正文写明疑在哪）
see_also: ["[[相关概念A]]", "[[相关概念B]]"]   # 带引号的列表，Obsidian 才认得出是链接
---
```

正文规矩：
- **先给结论，再展开。** 开头两三句话把这个概念说清楚。
- **引用原话要注明出处**（材料名 + 页码 / 时间码 / 章节）。
- **提到别的概念就加 `[[链接]]`**，指向还不存在的页也可以——那是待写清单。

## 3. 录入流程

1. 读 `wiki/index.md`，知道库里已有哪些页。
2. 读一份新材料（长材料分段读）。
3. 逐个概念判定：已有页 → 就地更新；新概念 → 新建；材料只提了名字没讲内容 → 不建页，只留 `[[链接]]`。
4. 更新 `index.md`（新页加一行，改过的页改日期）。
5. 在 `log.md` 的 `# 操作日志` 标题正下方追加一条（最新在上）：日期 / 材料路径 / 新建了哪些 / 更新了哪些 / 留作断链的。

**一份材料处理完、落盘、记账，再读下一份。**

**硬约束：原材料里没有的，不许写进 wiki。** 需要推断的标 `status: 存疑` 并写明疑在哪。

## 4. 体检

运行库根目录的 `lint.py`（`python3 lint.py`），检查：
- 断链：`[[]]` 指向不存在的页（**只列出，不自动建页**）
- 没被 `index.md` 收录的页 → 补进 index
- 重复 title（同概念两页 = 复利失效）→ 合并
- frontmatter 缺字段 → 补

## 5. 和 Obsidian 的关系

**这个文件夹直接作为 Obsidian 仓库打开。** AI 负责写，Obsidian 负责看：

| Obsidian 提供 | 靠什么 |
|---|---|
| 反向链接、关系图谱 | 正文里的 `[[链接]]` |
| Bases 视图（表格 / 卡片 / 列表，可按属性分组） | frontmatter |

`wiki/知识库看板.base` 是预配好的视图：按状态看板 / 按分类总表 / 待补的。
原生拖拽 Kanban 视图要 Obsidian 1.14 起，卡片视图按 `status` 分组效果等价。

## 6. 怎么接进工作流

- **产出 → 库**：工作流阶段收尾时，把产出放进 `raw/` 再录入。概念页只写结论并附原文位置，**不把全文搬进 wiki**。
- **库 → 下次开工**：开工前先读 `wiki/index.md` 定位，再读相关概念页，带着已有结论开始。

**一个只进不出的库是垃圾场，不是知识库。**
