# 工作台设计 · 加一个「主题样式」组件

**这个 skill 只做一件事：** 给一个已经能跑的学术工作台 HTML，加上一个可以点着切换外观的「主题样式」组件。

功能是对的、流程是通的，缺的是它看起来像不像一个正经东西。而"像不像"这件事**不该靠一次性改配色来定**——
改一次配色，只是拿你此刻的一个念头换掉 AI 此刻的一个念头。做一个主题组件，是把这个决定权留在界面上，以后随时改主意。

顺带还有一个更重要的好处：**主题切换逼你先有一套令牌。**
观感值散落在几十处 CSS 里是切不动的。所以这一步做完，工作台会从"一堆随手写的值"变成"一套可管理的值"——
专业和业余的差别不在某一个颜色，在有没有一套值。

## 硬约束（违反任何一条都算没做对）

1. **不动布局结构，不动功能。** 不增删场景卡、不改字段、不改按钮行为、不重排 DOM。
   能碰的只有观感层：颜色、字体、字号、字重、边框、阴影。
   **唯一允许新增的 DOM 是主题选择器本身**——一个下拉或一排小按钮，放在不抢戏的地方。
2. **两遍法，不许一遍写完。** 第一遍只出计划（令牌表 + 三套主题方向 + 组件放哪），**停下来等确认**；第二遍才动文件。
   用户说"你直接改"也要先把计划贴出来——可以不等回复就接着做，但计划必须可见。
3. **改之前先备份。** 没有备份就先拷一份带时间戳的副本，告诉用户备份在哪。
4. **第一套主题必须是「原样」。** 把工作台现在的长相原封不动收成第一套主题。
   这是用户的安全绳：新主题哪里不对，点回「原样」就回去了。
5. **不许编。** 说不清为什么这么改就直说；没见过参考图就别猜用户想要什么。

---

## 第一遍 · 出计划（不动文件）

**先问自己：这个工作台是干什么的、给谁用的。**
读项目指令文件（`AGENTS.md` / `CLAUDE.md`）和工作台设计文件，从那里判断用途和使用者；读不到再问用户一句，别凭工作台的名字臆断。

然后出一份**紧凑的计划**，三块，全部写完再停。

### 计划第一块 · 令牌表 + 归并清单

先扫一遍文件，把现在实际用到的观感值全列出来——**包括那些散值**（15px、随手写的灰）。再归并成一套 CSS 变量：

| 组 | 规格 |
|---|---|
| 色 | 主色 1 个；中性色 4 档（页面底 / 卡片与边框 / 次要文字 / 主要文字）；状态色按需，最多 3 个 |
| 字号 | 只留 5 档左右，成比例，别随手写 15px、17px |
| 间距 | 一个阶梯（如 4 / 8 / 12 / 16 / 24 / 32），全站只用这几个数 |
| 圆角 | 2 档 |
| 阴影 | 2 档，能不用就不用 |

给出**归并清单**：哪个散值归到哪一档。这是用户唯一能看出你有没有顺手改了长相的地方，别省。

**令牌名按角色起（`--text-muted`），不按长相起（`--gray-3`）。**
主题一换，`--gray-3` 可能根本就不是灰的——按长相起的名字第二天就开始骗人。

**说清哪些值不进主题。** 间距、圆角、字号阶这类结构性的值全站共用一份，**不随主题变**；
随主题变的只有色、字族、字重这一小撮。想让"切主题"顺带切布局，那是在改结构，违反硬约束 1。

### 计划第二块 · 三套主题的方向

给**三套气质明显不同**的主题——不是三个色相不同的同一套。每套写四行：

- **名字**：一个词，用户在下拉里看到的就是它（"素白""夜航""纸页"）。
- **色**：4–6 个命名色值（十六进制），每个色说清角色（底色 / 卡片 / 主色 / 文字 / 次要文字 / 状态色）。
- **字**：一到两个字族。用两个就让它们**明显不同**（比如衬线标题 + 无衬线正文），别用两个长得差不多的无衬线。
- **一句话**：这套想做成什么感觉，以及**把胆子花在哪一处**——
  每套挑一个地方做得有记忆点（标题区 / 当前项目横幅 / 主按钮），其余保持安静克制。三处都想出彩，结果是三处都吵。

**用户给了参考图**（截图直接拖进对话框）：先复述你从图里读到的风格——色感、字重对比、留白量、边框和圆角的性格、密度，
三五条，等用户确认再动手。**照风格，不照结构**：参考图的布局跟这个工作台没关系，不要搬。
一张参考图对应其中一套主题，另外两套仍然要你自己出——用来给它当参照，让用户挑得出来。

### 计划第三块 · 组件长什么样

说清三件事：**放在哪**（导航底部、页眉右上角这类不抢戏的位置）、**长什么样**（下拉还是一排小按钮）、
**怎么记住**（`localStorage` 存一个键，刷新和重开都还是上次那套）。

计划贴完，**停下来等确认。**

## 第二遍 · 落地（确认后一步一步来）

顺序不能颠倒。每步做完停一下，让用户刷新看过再进下一步：

1. **收令牌。** 在 `:root` 里定义变量，把全站散值替换成 `var(--…)`。
   **这一步做完，工作台应该和原来一模一样**——像素级一样。看起来变了，就是你替换错了值，退回去重来。
2. **加主题。** 每套主题是一组变量覆盖，挂在根元素的一个属性上（如 `:root[data-theme="night"]{ --bg:…; }`）。
   `:root` 里那套就是「原样」，不用另写一份。
3. **加组件。** 选择器负责改根元素上那个属性，并把选择写进 `localStorage`；页面加载时先读回来再渲染。
   读不到就用「原样」，不要报错，也不要白屏闪一下。
4. **自查一遍再交。** 三套主题各点一遍，看有没有哪一处没跟着变。
   **漏网的那一处，一定是还有硬编码的颜色没收进令牌**——回第 1 步补上，不许在主题里打补丁。

---

## 产出与完成标准

每做完一步，给两样：

1. **改动清单**——改了哪几处、为什么。收令牌那一步附归并清单。
2. **怎么验证**——告诉用户刷新后该看哪里，以及功能有没有被碰（应该没有）。

**完成标准三条，缺一条这轮都不算成：**

- 点下拉换主题，整个页面**没有一处**留在旧配色上；
- 刷新之后，还是上次选的那一套；
- 换回「原样」，工作台和动手之前一模一样——**所有按钮照常能点，字段一个没少，生成的 prompt 一字不差。**

功能坏了一处，这一轮就算失败，先退回备份再说。
